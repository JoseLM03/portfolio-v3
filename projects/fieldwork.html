01 / THE PROBLEM

An AI answer isn't the same as evidence.

Product research is useful only when you can trace conclusions back to their sources.

My goal was to build a research workflow that does more than generate a plausible-sounding report. It needed to collect real search results, preserve source references, handle failures honestly, and enforce boundaries on what the model could submit.

Fieldwork accepts a product idea and optional cost inputs, launches a research job, shows activity as it runs, and saves the resulting report with citations and limitations. The application is a research aid—not a source of independently verified market intelligence.

02 / HOW IT WORKS

One agent. Bounded tools. Verified references.

The system keeps the model's decisions separate from the server's rules. The agent chooses from validated tools; the backend decides what evidence and calculations are accepted.

03 / ENGINEERING

Decisions behind the build.

01

Evidence comes from the server.

The model selects source IDs and excerpts. Server-side code resolves exact quotes and rejects missing, mismatched, or duplicate references rather than trusting invented citations.

02

Tool use has limits.

Native Ollama calls are restricted to a validated tool registry, with bounds on turns, calls, request time, and recovery behavior.

03

Research is a durable job.

A SQL-backed queue tracks jobs and tool events, supports session-private history, and preserves explicit failed or partial states rather than silently losing errors.

04

Numbers don't come from guesses.

Optional contribution-margin calculations use Decimal arithmetic and only the original user-supplied cost scenario. Without enough inputs, the app explains the limitation.

What this does not prove

Fieldwork is not publicly deployed. Production hosting, full browser/accessibility acceptance, load behavior, and penetration testing were not verified at this release. Exact citations establish provenance, not the truth of outside sources. The README and verification record disclose these limits.

05 / TAKEAWAY

Good AI systems need ordinary engineering.

The most valuable work wasn't just getting a model to answer. It was building validation, error handling, persistence, and tests around it.

Fieldwork helped me practice full-stack API boundaries, asynchronous job execution, external provider integration, schema design, and the distinction between a convincing model output and a verifiable system result.
