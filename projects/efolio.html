01 / THE PROBLEM

Academic assessment requires structured evidence, not scattered files.

University degree programs require continuous tracking of student learning outcomes across semesters for accreditation, but evidence is often scattered across disparate tools.

Accreditation boards (such as ABET and SACSCOC) evaluate academic degree programs by assessing direct evidence of student learning. In practice, however, student coursework, evaluation rubrics, and faculty scoring frequently live in separate spreadsheets, email threads, and course folders. This fragmentation creates significant overhead when administrators need to aggregate program-wide outcome data.

Furthermore, an assessment system must accommodate distinct stakeholder responsibilities: students need a clean interface to curate work artifacts, faculty require clear rubrics to score competencies, and administrators need high-level reports across cohorts without exposing unauthorized evaluation records across classes.

eFolio addresses this by providing a unified, multi-role web platform: a central repository for student portfolio artifacts, structured evaluation workflows for faculty, and aggregated outcome reporting for institutional assessment.

Backend reporting, API rate limiting, and access controls.

eFolio was developed as a collaborative senior capstone project at Georgia Gwinnett College. My primary technical contributions were delivered through merged pull request #76, focusing on data reporting services, API hardening, role-based endpoint protection, and notification controls, supported by manual API testing and peer code reviews.

01

Portfolio Content Reporting (PR #76)

Authored backend data extraction and aggregation queries to compile student portfolio content, submission timestamps, and evaluation statuses into structured reports. This enabled faculty and academic reviewers to audit student progress and institutional outcomes across course sections without manual compilation.

02

API Rate Limiting & Abuse Prevention (PR #76)

Configured Express rate-limiting middleware to guard authentication endpoints and data-intensive reporting queries against burst traffic and brute-force enumeration. Established windowed request thresholds to ensure stable server operation during peak assessment deadlines.

03

Role-Based Endpoint Restrictions (PR #76)

Enforced role-based access control (RBAC) across Express routing middleware, verifying user permissions so that students, faculty, and administrators access only their authorized views. Ensured that sensitive scoring rubrics and aggregate assessment data remain inaccessible to unauthorized client requests.

04

Notification Preference Controls (PR #76)

Implemented configurable notification settings allowing users to control alert preferences for key portfolio events, such as milestone submissions and evaluation completion, reducing notification fatigue while keeping stakeholders informed.

04 / FEATURES

Core capabilities of the assessment platform.

01

Student Artifact Management

Students upload and organize learning artifacts (documents, presentations, project reflections) linked to specific courses, building a progressive portfolio demonstrating mastery of degree competencies.

02

Faculty Rubric Assessment

Instructors evaluate submitted artifacts against standardized departmental rubrics, recording criteria-specific scores and qualitative feedback directly into the platform.

03

Aggregated Content Reporting

Administrative dashboards query portfolio completion rates and rubric scores across cohorts, producing structured summaries for accreditation reviews without manual data wrangling.

04

Defensive Endpoint Security

Layered rate limiting and role verification prevent unauthorized access, protecting sensitive student grades and preventing server overload during end-of-semester submission peaks.

05 / VERIFICATION

What this does not represent

eFolio is an academic capstone platform developed for institutional assessment coursework, not a deployed commercial SaaS product. It is maintained in a private organization repository (GGC-SD/efolio), does not process payment transactions, and is not hosted on a public production domain.

06 / TAKEAWAY

What I learned collaborating on an enterprise-scale capstone.

Working on a multi-role institutional platform emphasized the importance of defensive API design, role boundaries, and disciplined branch integration.

In an academic capstone, different team members build features concurrently. Coordinating shared Express routes and MongoDB collections required agreeing on clean API contracts early, ensuring that adding rate limiting or reporting queries didn't interfere with ongoing work.

Implementing security-focused features like rate limiting and role-based restrictions reinforced that authorization isn't just a frontend concern—every backend endpoint must independently defend its data boundaries. Contributing to eFolio gave me valuable experience building full-stack software that balances user needs with strict access controls.
